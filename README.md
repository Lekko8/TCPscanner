# portscan

Пакет Go для конкурентной проверки доступности TCP-портов на одном или
нескольких хостах. Реализует обычное TCP connect-сканирование средствами
стандартной библиотеки и предназначен для встраивания в другие приложения.

`Go 1.25.5` · `только стандартная библиотека` · `go test -race ./...`

## Возможности

- Один или несколько хостов: IPv4, IPv6 и DNS-имена.
- Списки портов, диапазоны и объединения диапазонов.
- Настраиваемое количество одновременных подключений.
- Настраиваемый таймаут TCP-подключения.
- Отмена через `context.Context` без зависших горутин.
- Структурированные состояния портов без сравнения текста ошибок.
- Ограниченный канал результатов и естественный backpressure.
- Повторное и конкурентное использование одного `Scanner`.
- Нет сторонних зависимостей и глобального изменяемого состояния.

## Требования

- Go 1.25.5 — версия зафиксирована в `go.mod`.
- Поддерживаются основные платформы Go: Windows, Linux, macOS, FreeBSD,
  OpenBSD, NetBSD, DragonFly, Solaris/illumos, AIX.
- Сторонние зависимости не требуются.

## Быстрый старт

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"tcpscanner/portscan"
)

func main() {
	scanner, err := portscan.New(
		portscan.WithConcurrency(100),
		portscan.WithConnectTimeout(500*time.Millisecond),
	)
	if err != nil {
		log.Fatal(err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), time.Minute)
	defer cancel()

	results, err := scanner.Scan(
		ctx,
		[]string{"192.168.1.10", "192.168.1.11"},
		portscan.Range(1, 1000),
	)
	if err != nil {
		// Некорректные хосты, порты или опции.
		log.Fatal(err)
	}

	for result := range results {
		fmt.Printf("%s:%d %s\n", result.Host, result.Port, result.State)
		if result.Err != nil {
			fmt.Printf("  причина: %v\n", result.Err)
		}
	}
}
```

## Публичный API

### Scanner

```go
func New(opts ...Option) (*Scanner, error)

func (s *Scanner) Scan(
	ctx context.Context,
	hosts []string,
	ports Ports,
) (<-chan Result, error)
```

`New` создаёт сканер с настройками по умолчанию:

- до 100 одновременных попыток подключения в рамках одного `Scan`;
- таймаут одного TCP-подключения — 5 секунд.

Нулевое значение `Scanner{}` также готово к использованию и эквивалентно
`New()` с настройками по умолчанию. `New` предпочтителен, потому что позволяет
задать лимиты и возвращает ошибку при некорректных опциях.

`Scan` принимает контекст, список хостов и набор портов. Возвращаемый канал
закрывается по завершении сканирования.

- Ошибка возвращается синхронно для некорректной конфигурации или входных
  данных, `nil`-контекста, `nil`-сканера либо уже отменённого контекста.
  Сетевые ошибки попадают в `Result.Err` соответствующего порта.
- Порядок результатов — порядок завершения проверок, а не порядок хостов
  или портов.
- Канал буферизован на `concurrency` элементов. Если потребитель перестал
  читать, воркеры блокируются: это осознанный backpressure, память не растёт
  бесконечно.
- Потребитель обязан дочитать канал либо отменить контекст.
- После отмены контекста новые проверки не запускаются, уже запущенные
  прерываются, после их завершения канал закрывается.
- Если `ctx` уже отменён, `Scan` возвращает ошибку контекста и не запускает
  сканирование.
- `nil`-контекст возвращает `ErrNilContext`, `nil`-сканер — `ErrNilScanner`.
- `Scanner` неизменяем после создания и безопасен для конкурентного
  использования, включая параллельные вызовы `Scan`.

### Опции

```go
func WithConcurrency(n int) Option
func WithConnectTimeout(d time.Duration) Option
```

| Опция | Описание | Ограничение |
|---|---|---|
| `WithConcurrency(n)` | Максимум одновременных TCP-подключений в одном `Scan` | `n > 0` |
| `WithConnectTimeout(d)` | Таймаут одного TCP handshake | `d > 0` |

Лимит конкурентности действует на один вызов `Scan`. Несколько параллельных
сканирований одним экземпляром `Scanner` допустимы, но каждое имеет собственный
лимит. Фазы DNS-резолвинга и подключений не пересекаются, поэтому одновременных
сетевых операций в одном сканировании не больше `n`.

`WithConnectTimeout` ограничивает только TCP handshake. DNS-резолвинг
ограничивается контекстом `Scan` и системным резолвером.

### Порты

```go
func Range(from, to int) Ports
func List(ports ...int) Ports
func Union(sets ...Ports) Ports
```

`Ports` — неизменяемый набор портов. Аргументы имеют тип `int`, а не `uint16`,
чтобы значения вне диапазона можно было явно диагностировать, а не терять при
приведении типа.

```go
ports := portscan.Union(
	portscan.Range(1, 1024),
	portscan.List(3306, 5432, 8080),
	portscan.Range(9000, 9100),
)
```

Валидация выполняется в `Scan`:

- допустимы порты `1..65535`;
- `0`, отрицательные значения и значения больше `65535` дают
  `ErrInvalidPort`;
- обратный диапазон (`Range(1000, 1)`) даёт `ErrInvalidPortRange`;
- пустой набор (`Ports{}`, `List()`, `Union()`) даёт `ErrNoPorts`;
- повторы удаляются, итоговый список сортируется по возрастанию.

Пример: `Union(Range(10, 12), List(1, 10), Range(5, 6))` разворачивается
в `[1, 5, 6, 10, 11, 12]`.

### Result

```go
type Result struct {
	Host     string
	IP       net.IP
	Port     uint16
	State    State
	Duration time.Duration
	Err      error
}
```

| Поле | Описание |
|---|---|
| `Host` | Хост в нормализованном виде. Литеральные IP приводятся к канонической форме (`[::1]` → `::1`), DNS-имена сохраняются как переданы |
| `IP` | Фактически проверенный адрес; `nil`, если имя не удалось разрешить |
| `Port` | Проверенный порт |
| `State` | Структурированное состояние |
| `Duration` | Время TCP-подключения; ноль, если попытка не выполнялась |
| `Err` | Причина для `timeout`, `unreachable`, `canceled`, `error`; `nil` для `open` и `closed` |

`Err` носит информативный характер. Определять состояние нужно по `State`,
а не по тексту ошибки.

### State

| Состояние | Значение |
|---|---|
| `StateOpen` | TCP-соединение установлено и сразу закрыто сканером |
| `StateClosed` | Соединение явно отклонено (например, RST / connection refused) |
| `StateTimeout` | Подключение не уложилось в `WithConnectTimeout` |
| `StateUnreachable` | ОС сообщила, что узел или сеть недоступны |
| `StateCanceled` | Проверка отменена через контекст |
| `StateError` | Другая ошибка, включая ошибку DNS-резолвинга |

Классификация не использует сравнение строк:

- `errors.Is` / `errors.As` для контекстных ошибок;
- `net.Error.Timeout()` и `os.ErrDeadlineExceeded` для таймаутов;
- `syscall.Errno` для POSIX-ошибок (`ECONNREFUSED`, `ECONNRESET`,
  `ETIMEDOUT`, `EHOSTUNREACH`, `ENETUNREACH` и родственных);
- отдельные числовые WinSock-коды для Windows;
- fallback для платформ без `syscall.Errno`.

## Поведение в краевых случаях

### Хосты

| Вход | Поведение |
|---|---|
| `""`, строка из пробелов | `ErrInvalidHost` синхронно |
| `999.999.999.999` | `ErrInvalidHost` как заведомо некорректный IP |
| `10.0.0.0/8` | `ErrInvalidHost`: CIDR не поддерживается |
| Некорректный IPv6, например `2001:db8::zz` | `ErrInvalidHost` |
| Неразрешимое DNS-имя | `StateError` на каждый порт, ошибка резолвера в `Err` |
| Повторяющийся хост | Дубликат удаляется |
| DNS-имя с несколькими A/AAAA | Проверяется каждый уникальный адрес |
| IPv6 в скобках, `[::1]` | Поддерживается, в `Host`/`IP` попадает `::1` |
| IPv6 с зоной, `fe80::1%eth0` | Поддерживается для литерала |

Дубликаты определяются по каноническому IP для литералов и без учёта регистра
и завершающей точки для DNS-имён (`Example.COM`, `example.com` и
`example.com.` — один хост). Разные DNS-имена, указывающие на один IP, остаются
разными целями, потому что в `Result.Host` важно исходное имя.

DNS-имя резолвится один раз за сканирование. Все полученные адреса
дедуплицируются, для каждого адреса и порта создаётся отдельный `Result`.
Ошибка резолвинга одного имени не прерывает сканирование остальных хостов.
Пустой список адресов без ошибки резолвера трактуется как `ErrNoAddresses`.

### Порты

| Вход | Поведение |
|---|---|
| `0` | `ErrInvalidPort` |
| `65536`, отрицательное значение | `ErrInvalidPort` |
| `Range(1000, 1)` | `ErrInvalidPortRange` |
| Повторяющиеся порты | Удаляются |
| Пустой набор | `ErrNoPorts` |
| `Range(1, 65535)` | Корректный диапазон |

## Конкурентность и отмена

Сканирование устроено как ограниченный worker pool:

1. Входные данные проверяются синхронно.
2. DNS-имена резолвятся конкурентно, не более `concurrency` одновременно.
3. Задания «адрес × порт» передаются воркерам через канал.
4. Воркер выполняет `net.Dialer.DialContext`, при успехе сразу закрывает
   соединение и отправляет `Result` в буферизованный канал результатов.

Гарантии:

- число одновременных подключений в одном `Scan` не превышает лимит;
- после отмены новые задания не отправляются;
- уже запущенные подключения прерываются контекстом;
- `Scan` дожидается завершения запущенных операций и только затем закрывает
  канал;
- успешные соединения всегда закрываются;
- при медленном потребителе используется backpressure;
- один `Scanner` можно использовать повторно и параллельно.

Особенности отмены:

- проверки, которые не успели начаться, не попадают в результаты;
- прерванные проверки могут попасть в результаты со `StateCanceled`;
- доставка отменённых результатов best effort: если потребитель уже не читает,
  результат отбрасывается, чтобы канал мог закрыться, а горутины завершиться;
- если контекст уже отменён на момент вызова `Scan`, возвращается ошибка
  контекста.

## Примеры использования

### Собрать все результаты

```go
func scanAll(
	ctx context.Context,
	s *portscan.Scanner,
	hosts []string,
	ports portscan.Ports,
) ([]portscan.Result, error) {
	results, err := s.Scan(ctx, hosts, ports)
	if err != nil {
		return nil, err
	}

	var out []portscan.Result
	for result := range results {
		out = append(out, result)
	}
	return out, nil
}
```

### Только открытые порты

```go
for result := range results {
	if result.State == portscan.StateOpen {
		fmt.Printf("%s (%s):%d открыт\n", result.Host, result.IP, result.Port)
	}
}
```

### Отмена по сигналу

```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
defer stop()

results, err := scanner.Scan(ctx, hosts, portscan.Range(1, 65535))
if err != nil {
	return err
}

for result := range results {
	handle(result)
}
// Канал закроется после отмены, когда завершатся уже запущенные проверки.
```
