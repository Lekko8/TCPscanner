# portscan — TCP connect-сканер портов на Go

Небольшой Go-пакет для конкурентной проверки доступности TCP-портов на одном
или нескольких хостах. Пакет предназначен для встраивания в другие приложения:
он не зависит от CLI, HTTP-фреймворков, баз данных и брокеров сообщений.

Реализовано только обычное TCP connect-сканирование средствами стандартной
библиотеки. SYN/UDP/raw-сокеты, определение ОС, обход фаерволов и эксплуатация
уязвимостей не реализованы и не являются целью пакета.

- Go 1.25.5
- Только стандартная библиотека, сторонних зависимостей нет
- Нет глобального изменяемого состояния
- `Scanner` безопасно использовать повторно и конкурентно
- Проходит `go test -race ./...`

## Быстрый старт

```go
package main

import (
	"context"
	"fmt"
	"time"

	"tcpscanner/portscan"
)

func main() {
	scanner, err := portscan.New(
		portscan.WithConcurrency(100),
		portscan.WithConnectTimeout(500*time.Millisecond),
	)
	if err != nil {
		panic(err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), time.Minute)
	defer cancel()

	results, err := scanner.Scan(
		ctx,
		[]string{"192.168.1.10", "192.168.1.11"},
		portscan.Range(1, 1000),
	)
	if err != nil {
		// Ошибки конфигурации и входных данных возвращаются сразу.
		panic(err)
	}

	for result := range results {
		fmt.Printf("%s:%d %s\n", result.Host, result.Port, result.State)
		if result.Err != nil {
			fmt.Printf("  причина: %v\n", result.Err)
		}
	}
}
```

Диапазоны, отдельные порты и их объединения:

```go
ports := portscan.Union(
	portscan.Range(1, 1024),
	portscan.List(3306, 5432, 8080),
	portscan.Range(9000, 9100),
)
```

## Публичный API

### `New` и опции

```go
func New(opts ...Option) (*Scanner, error)
```

`Scanner` — неизменяемый после создания объект. Нулевое значение `Scanner{}`
готово к использованию и эквивалентно `New()` с настройками по умолчанию;
`New` предпочтителен, потому что позволяет задать лимиты и возвращает ошибку
при некорректных опциях.

Создаёт сканер с настройками по умолчанию:

- `WithConcurrency(100)` — до 100 одновременных попыток подключения в рамках
  одного вызова `Scan`;
- `WithConnectTimeout(5 * time.Second)` — таймаут одного TCP-подключения.

Обе опции проверяют значения и возвращают `ErrInvalidOption` при некорректном
аргументе. `New` также возвращает `ErrInvalidOption` для `nil`-опции.

```go
func WithConcurrency(n int) Option
func WithConnectTimeout(d time.Duration) Option
```

Лимит конкурентности действует на один вызов `Scan`. Несколько параллельных
сканирований одним экземпляром `Scanner` допустимы, но каждое из них имеет
собственный лимит. Фазы DNS-резолвинга и подключений не пересекаются, поэтому
одновременных сетевых операций в одном сканировании не больше `n`.

`WithConnectTimeout` ограничивает только TCP handshake. DNS-резолвинг
ограничивается контекстом `Scan` и системным резолвером.

### `Scan`

```go
func (s *Scanner) Scan(ctx context.Context, hosts []string, ports Ports) (<-chan Result, error)
```

Принимает контекст, список хостов и набор портов. Возвращает канал результатов
и ошибку.

- Ошибка возвращается синхронно только для некорректной конфигурации или
  входных данных. Сетевые ошибки попадают в `Result.Err` соответствующего
  порта.
- Канал закрывается, когда сканирование завершено.
- Порядок результатов — порядок завершения проверок, а не порядок хостов или
  портов.
- Канал буферизован на `concurrency` элементов. Если потребитель перестал
  читать, воркеры блокируются — это сознательный backpressure, память не растёт
  бесконечно.
- Потребитель обязан либо дочитать канал, либо отменить контекст. После отмены
  контекста блокировки снимаются, и канал закрывается.
- Если `ctx` уже отменён, `Scan` возвращает ошибку контекста и не запускает
  сканирование.
- `nil`-контекст возвращает `ErrNilContext`, `nil`-сканер — `ErrNilScanner`.

### `Ports`

```go
func Range(from, to int) Ports
func List(ports ...int) Ports
func Union(sets ...Ports) Ports
```

`Ports` — неизменяемый набор портов. Аргументы имеют тип `int`, а не `uint16`,
чтобы можно было явно сообщить об ошибке для значений вне диапазона, а не
молча получить переполнение.

Валидация выполняется в `Scan`:

- допустимы порты `1..65535`;
- `0`, отрицательные значения и значения больше `65535` дают
  `ErrInvalidPort`;
- обратный диапазон (`Range(1000, 1)`) даёт `ErrInvalidPortRange`;
- пустой набор (`Ports{}`, `List()`, `Union()`) даёт `ErrNoPorts`;
- повторы удаляются, итоговый список сортируется по возрастанию.

Пример: `Union(Range(10, 12), List(1, 10), Range(5, 6))` разворачивается в
`[1, 5, 6, 10, 11, 12]`.

### `Result` и `State`

```go
type Result struct {
	Host     string
	IP       net.IP
	Port     uint16
	State    State
	Duration time.Duration
	Err      error
}
```

- `Host` — хост в нормализованном виде. Литеральные IP приводятся к
  канонической форме (`[::1]` → `::1`, IPv4-mapped IPv6 → IPv4). DNS-имена
  сохраняются как переданы, без ведущих и хвостовых пробелов.
- `IP` — фактически проверенный адрес. `nil`, если имя не удалось разрешить.
- `Port` — проверенный порт.
- `Duration` — время TCP-подключения. Ноль, если попытка не выполнялась
  (например, из-за ошибки DNS).
- `Err` — причина для `StateTimeout`, `StateUnreachable`, `StateCanceled` и
  `StateError`. Для `StateOpen` и `StateClosed` равен `nil`: явный отказ
  соединения — это успешно полученный результат проверки, а не ошибка сканера.
- `State` — структурированное состояние; определять его по тексту `Err`
  не нужно и не следует.

Состояния:

| Состояние | Значение |
|---|---|
| `StateOpen` | TCP-соединение установлено и сразу закрыто сканером |
| `StateClosed` | соединение явно отклонено (например, RST / connection refused) |
| `StateTimeout` | подключение не уложилось в `WithConnectTimeout` |
| `StateUnreachable` | ОС сообщила, что узел или сеть недоступны |
| `StateCanceled` | проверка отменена через контекст |
| `StateError` | другая ошибка, включая ошибку DNS-резолвинга |

Классификация не использует сравнение строк. Используются:

- `errors.Is` / `errors.As` для контекстных ошибок;
- `net.Error.Timeout()` и `os.ErrDeadlineExceeded` для таймаутов;
- `syscall.Errno` для `ECONNREFUSED`, `ECONNRESET`, `ETIMEDOUT`,
  `EHOSTUNREACH`, `ENETUNREACH` и родственных ошибок;
- отдельное сопоставление кодов WinSock для Windows (в `syscall` они не всегда
  совпадают с POSIX-константами).

### Ошибки

| Ошибка | Когда возникает |
|---|---|
| `ErrInvalidOption` | некорректное значение опции, `nil`-опция |
| `ErrNilScanner` | `Scan` вызван на `nil *Scanner` |
| `ErrNilContext` | в `Scan` передан `nil` контекст |
| `ErrNoHosts` | пустой список хостов |
| `ErrInvalidHost` | пустой, некорректный или неподдерживаемый хост |
| `ErrNoPorts` | пустой набор портов |
| `ErrInvalidPort` | порт вне `1..65535` |
| `ErrInvalidPortRange` | начало диапазона больше конца |
| `ErrNoAddresses` | DNS-имя разрешилось в пустой список адресов |

Все они пригодны для `errors.Is`.

## Поведение в краевых случаях

### Хосты

| Вход | Поведение |
|---|---|
| `""`, строка из пробелов | `ErrInvalidHost` синхронно |
| `999.999.999.999` | `ErrInvalidHost` как заведомо некорректный IP |
| `10.0.0.0/8` | `ErrInvalidHost`: CIDR не поддерживается |
| некорректный IPv6, например `2001:db8::zz` | `ErrInvalidHost` |
| неразрешимое DNS-имя | результат на каждый порт: `StateError`, `Err` — ошибка резолвера |
| повторяющийся хост | дубликат удаляется |
| DNS-имя с несколькими A/AAAA | проверяется каждый уникальный адрес |
| IPv6 в скобках, `[::1]` | поддерживается, в `Host`/`IP` попадает `::1` |
| IPv6 с зоной, `fe80::1%eth0` | поддерживается для литерала |

Дубликаты определяются по каноническому IP для литералов и без учёта регистра
и завершающей точки для DNS-имён (`Example.COM`, `example.com` и
`example.com.` — один хост). Разные DNS-имена, указывающие на один IP, остаются
разными целями, потому что в `Result.Host` важно исходное имя.

DNS-имя резолвится один раз за сканирование. Все полученные адреса
дедуплицируются, для каждого адреса и порта создаётся отдельный `Result`.
Если имя не разрешилось, сканирование остальных хостов не прерывается: для
каждого запрошенного порта этого хоста возвращается `StateError`.

Пустой список адресов без ошибки резолвера трактуется как `ErrNoAddresses`.

### Порты

| Вход | Поведение |
|---|---|
| `0` | `ErrInvalidPort` |
| `65536`, отрицательное значение | `ErrInvalidPort` |
| `Range(1000, 1)` | `ErrInvalidPortRange` |
| повторяющиеся порты | удаляются |
| пустой набор | `ErrNoPorts` |
| `Range(1, 65535)` | корректный диапазон |

## Конкурентность, отмена и закрытие соединений

Сканирование устроено как ограниченный worker pool:

1. Входные данные проверяются синхронно.
2. DNS-имена резолвятся конкурентно, не более `concurrency` одновременно.
3. Для каждой пары «адрес × порт» задания отправляются воркерам через
   небуферизованный канал.
4. Каждый воркер делает `net.Dialer.DialContext`, при успехе немедленно
   закрывает соединение и отправляет `Result` в буферизованный канал
   результатов.

Гарантии:

- число одновременных подключений в одном `Scan` не превышает заданный лимит;
- после отмены контекста новые задания не отправляются;
- уже запущенные подключения прерываются контекстом;
- `Scan` дожидается завершения всех запущенных операций и только потом
  закрывает канал результатов;
- успешные соединения всегда закрываются;
- при медленном потребителе используется backpressure, без неограниченной
  очереди;
- ошибки не сравниваются по тексту;
- один `Scanner` можно использовать повторно и параллельно.

Особенности отмены:

- проверки, которые не успели начаться, не попадают в результаты;
- проверки, прерванные контекстом, могут попасть в результаты со
  `StateCanceled`;
- доставка отменённых результатов best effort: если потребитель уже не читает,
  результат отбрасывается, чтобы канал мог закрыться, а горутины — завершиться;
- если контекст уже отменён на момент вызова `Scan`, возвращается ошибка
  контекста.

## Примеры

### Собрать все результаты

```go
func scanAll(ctx context.Context, s *portscan.Scanner, hosts []string, ports portscan.Ports) ([]portscan.Result, error) {
	results, err := s.Scan(ctx, hosts, ports)
	if err != nil {
		return nil, err
	}

	var out []portscan.Result
	for result := range results {
		out = append(out, result)
	}
	return out, nil
}
```

### Отмена по сигналу

```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
defer stop()

results, err := scanner.Scan(ctx, hosts, portscan.Range(1, 65535))
if err != nil {
	return err
}

for result := range results {
	// Канал закроется после отмены, когда завершатся уже запущенные проверки.
	handle(result)
}
```

### Только открытые порты

```go
for result := range results {
	if result.State == portscan.StateOpen {
		fmt.Printf("%s (%s):%d открыт\n", result.Host, result.IP, result.Port)
	}
}
```

## Тестирование

```bash
go test -race ./...
```

Тесты не требуют внешней сети:

- валидация и разворачивание портов, включая 0, значения больше 65535,
  обратные диапазоны и дубликаты;
- валидация и нормализация IPv4/IPv6/DNS-имён, скобки, зоны, дубликаты;
- классификация ошибок подключения без анализа текста ошибок, включая
  платформенные `syscall.Errno`;
- интеграционная проверка `open`/`closed` на loopback-адресе и проверка того,
  что сканер закрывает установленное соединение;
- ограничение конкурентности;
- отмена в фазе резолвинга и в фазе подключений;
- медленный потребитель и закрытие канала после отмены;
- DNS-ошибки, пустой список адресов, несколько адресов у одного имени;
- повторное и конкурентное использование одного `Scanner`.

## Принятые архитектурные решения

- **Канал результатов вместо среза.** Пакет отдаёт результаты по мере
  готовности, не накапливая весь результат в памяти. Буферизованный канал
  ограничивает память и даёт естественный backpressure.
- **Разделение ошибок входа и сетевых ошибок.** Некорректные хосты, порты и
  опции — это ошибка вызова. Недоступный порт или неразрешимое имя — это
  результат проверки, который не должен ломать сканирование остальных целей.
- **Резолвинг до подключений.** DNS выполняется один раз на имя, все адреса
  проверяются отдельно. Это делает поведение предсказуемым и не зависит от
  того, какой адрес выберет `net.Dial` при повторных попытках.
- **Явная платформенная классификация ошибок.** Windows возвращает коды
  WinSock (`10061` и т. п.), которые не равны POSIX-константам из `syscall`.
  Поэтому используются отдельные файлы для Windows и Unix, а не сравнение
  строк.
- **`int` в конструкторах портов.** Позволяет корректно диагностировать
  значения вне `uint16`, а не терять их при приведении типа.
- **Строгая валидация.** Строки вида `999.999.999.999`, CIDR и имена с
  недопустимыми символами отклоняются сразу, а не превращаются в долгий и
  бесполезный DNS-запрос.
- **Отсутствие глобального состояния.** Вся конфигурация хранится в
  неизменяемом `Scanner`; состояние сканирования локально для каждого вызова.

## Ограничения

- Нет SYN-, UDP- и raw-сканирования, определения ОС и обхода фаерволов.
- Нет CIDR; CIDR можно добавить отдельным конструктором `Ports`/хостов, не
  меняя основной API.
- Нет автоматических повторов и rate limiting. При необходимости их можно
  добавить опциями, не меняя `Result` и состояния.
- DNS-резолвинг ограничен контекстом и системным резолвером, а не
  `WithConnectTimeout`.
- Поддерживаются числовые порты; имена сервисов (`http`) не принимаются.
- IDN-имена должны передаваться в punycode-форме.
- IPv6-зона поддерживается для литеральных адресов; DNS-резолвер зоны не
  возвращает.
